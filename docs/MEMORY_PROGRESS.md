# 剧情进度与记忆整理（1.2.11）

## 本幕资料

在“剧本与记忆”中，为人物、任务、线索、事实设置“所属章节”。
公开资料只可关联公开章节，秘密资料仍需秘密权限。
房主选择“本幕章节”并点击“使用本幕资料”后：

- 一次启用本章及其关联的有效公开资料，取消其他公开参考条目。
- 不公开秘密，不恢复归档资料，不改写正文。
- 修改后的条目建立新版本，战役版本推进一次；请求重试不重复操作。
- 总标题／正文超过24000字时整次拒绝，不留下半套选择。
- 主持运行中或有未保存编辑时不能切换。跨幕事实可在切换后单独勾选。

API：`POST /lore/focus`，请求 `{client_id,version,chapter_id}`。

## 任务和线索

资料增加 `chapter_id` 与 `progress`：

- 任务 `quest`：`not_started`、`in_progress`、`completed`、`failed`。
- 线索 `clue`：`undiscovered`、`discovered`、`resolved`。
- 其他分类进度为空。

进度不等于权限：公开的“未发现”线索仍然能被玩家读到，真正未揭露的秘密请保存为“主持秘密”。
旧记录未填写进度仍可读取；再次保存时使用该类型默认进度。

## 待确认的记忆

`complete.outcome` 新增可选字段：

```json
{
  "memory_suggestions": [
    {"kind":"fact","title":"钥匙的归还约定","content":"守夜人交出了钟楼钥匙，并提醒日落前归还。"}
  ]
}
```

最多5条，分类为fact/npc/quest/clue，标题最多100字，正文最多2000字。
内置主持工具与外部示例的工具schema已包含此字段；旧接入不提供仍可正常完成。

建议与正式叙述同事务保存并绑定其事件编号；完成请求重试不会重复产生建议。
建议不出现在公开context、不更改场景或角色资源，也不直接创建长期事实。
只有真人房主可读建议及来源、载入编辑、明确采用或忽略。

- `GET /memory-suggestions`：最新100条，含状态和正式来源正文，仅房主。
- 保存新资料时可带 `suggestion_id`；同事务建资料与标记accepted。
  新条目默认秘密，房主核对后才决定是否公开或供主持参考。
- `POST /memory-suggestions/{id}/reject`：带client_id，标记rejected，不改既定事实。
- 已处理的建议不能重复采用。首次仅支持采用为新资料；如要合并已有NPC或任务，
  请核对建议后手工修改原条目，避免自动覆盖。

## 前情回顾

冒险日志中的“前情回顾与未解决事项”按需读取 `GET /recap`。
内容来自已保存的公开摘要、最近3条正式叙述（每条至多2000字，明确标注节选）、
最多20项未解决任务／线索及10条选中参考事实。只读，不调用AI、不自动生成新结论。
来源保留资料编号或叙述事件编号，秘密和归档内容不出现。

已完成／未达成的任务、已解决线索不列入“还未解决”。回顾不等于完整历史，遗漏数量有提示。
