# 主持人流式输出

从 1.2.7 起，娱乐模式的冒险日志可以在主持人生成正文时显示临时草稿。
这是模型生成中的真实预览，不是收到全文后的打字动画。

## 内置 AI

内置主持使用 Chat Completions `stream: true`，读取 SSE 工具调用参数。
仅预览 `finish_turn.narration`；结束本次时预览 `finish_turn.summary`。
不展示模型 reasoning、普通 content、其他工具参数或角色状态变更。
仍通过原有工具校验及 `/complete` 原子入档。供应商若忽略 stream 并返回完整 JSON，
仍可正常主持，但只能最终显示全文；供应商必须支持流式工具调用才能实时预览。

## 外部主持

原有 `/complete` 接口继续兼容。**只调用 `/complete` 的旧主持不会自动获得流式能力**；
需要在生成正文期间调用以下接口，或更新到本版 `scripts/campaign-agent.cjs`。
MCP 连接器新增 `campaign_stream` 工具。MCP 主持只有主动分批调用该工具时才会逐批显示，
服务端无法读取外部聊天平台中尚未提交的生成内容。

领取回合后，发送已经生成的**完整公开正文前缀**：

```http
POST /api/v1/campaigns/1/turns/42/stream
Authorization: Bearer <此战役主持令牌>
Content-Type: application/json
```

```json
{
  "lease": "<claim 返回的 lease>",
  "version": 20,
  "seq": 1,
  "narration": "门后传来轻轻的脚步声。"
}
```

后续请求使用 `seq: 2`、`3`…，`narration` 为至今生成的全文前缀，不是追加片段。
建议每 350–1000ms 合并发送一次，而非逐 token 请求。每个主持身份每分钟最多 300 次
流式写请求，使用独立限流桶，不挤占掷骰和完成请求。

- `version` 使用领取时的 `base_version`，`lease` 必须属于同一主持和仍有效的回合。
- 正文最多 12000 字符，空正文可清空预览。序号为 1–100000 的整数。
- 成功返回 `{"seq":1}`。丢失响应时可重发完全相同的最新序号与正文，不重复追加。
- 旧序号、相同序号但正文不同、过期租约、已完成回合返回 409；令牌失效返回 401。
- **不要传入 `client_id`**：流式接口以租约和 seq 幂等。最终 `/complete` 仍使用原有 `client_id`。
- 新租约可从 1 重新编号；旧租约的草稿不会出现在重试回合里。
- 仅发送玩家可见的叙述。草稿立即对全体战役成员可见，不可用来传递主持秘密或内部推理。

正文完成后照常提交 `/turns/42/complete`，携带完整 `outcome`、`lease`、`version`、
唯一 `client_id`。服务端在一个事务中保存正文和游戏状态；预览不写聊天记录、不修改场景、
生命值、资源或版本。最终结果不要求和草稿字节完全一致，以校验通过的 complete 为准。

## 客户端与恢复

服务器通过现有成员限定 WebSocket 发布 `campaign.stream` 通知（`campaign_id`）。
客户端请求 `GET /api/v1/campaigns/1/stream` 读取当前快照：

```json
{"draft":{"turn_id":42,"seq":2,"narration":"门后传来脚步声。守夜人提着灯。","expires_at":1795580000000}}
```

无有效草稿时为 `{"draft":null}`。GET 需要战役成员会话或该战役令牌，
不暴露 lease。页面收到通知立即刷新，另以 3 秒轮询兜底并在重新显示时恢复。
失败、暂停、版本改变、完成、令牌撤销或 180 秒租约过期后不返回旧草稿。
临时正文不逐 token 播报给屏幕阅读器；正式入档沿用日志播报。
阅读历史时沿用现有锚点保持，不强制跳到最底部。

## 验证

`go test ./...` 覆盖访问隔离、幂等、序号冲突、租约／版本／撤销失效、
原子完成去重及 SSE 中断与公开字段提取。
`npm run test:streaming` 使用隔离服务和无头浏览器，证明内置／外部模型响应仍打开时
正文已经可见、刷新恢复及单次入档，并捕获 1264、390、320px 布局。
