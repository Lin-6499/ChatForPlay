# 联合回合与恢复边界（1.2.14）

## 工具预算与时间

领取回合返回 `tool_budget`、`deadline_at`、`resuming`。
预算为 `min(28,max(8,2×行动人数+4))`：4人12步、12人28步，足够为每人准备／投骰后提交，
而不是所有队伍一律8步。预算按整个回合计算，重试不会无限追加工具步骤。

短租约仍为180秒。新增：

```http
POST /api/v1/campaigns/{id}/turns/{turn}/heartbeat
Content-Type: application/json
Authorization: Bearer <原主持令牌>
```

```json
{"lease":"领取时返回的原租约"}
```

有效期内心跳刷新短租约，但不能复活过期／暂停／已完成回合，也不能延长本次领取的
绝对执行截止时间（12分钟）。内置主持和新版Bot在模型／工具步骤前续租，每次模型请求最多50秒。
慢供应商仍可能触及时间上限；已完成的步骤保留，由房主检查后恢复，不无休止自动重试。

## 恢复不重做

内置主持保存初始公开上下文、模型工具选择和服务器工具回执。恢复时重放已保存的对话，
只继续缺失步骤；掷骰与检定继续复用原幂等回执。

外部Bot新增原子本地检查点，先保存工具选择再请求服务器，收到结果后保存回执。
固定每步操作编号，响应丢失后复用同一步输入，不重新选择骰式或重复扣资源。
默认目录为当前用户本地数据下 `LinChat/bot-state`，可用 `LINCHAT_BOT_STATE_DIR` 指定。
范围由战役地址、令牌与模型配置的哈希隔离，不写配置中的token／API key／lease，
但包含公开剧情和模型工具参数，请保护并备份该目录。已完成记录保留，不自动删除。

重试必须保持原主持身份和战役输入版本。换令牌／换模型配置导致检查点不可用，
或者房主改变了战役版本，系统会明确拒绝直接续跑，需恢复原环境或由房主接管／跳过。
这是一条保守保护：即便只是暂停／恢复推进了版本，也不会擅自把旧决策套入新版本。
旧Bot没有本地检查点的恢复回合，不能承诺自动安全续跑；新版Bot会停止并提示人工核对。

## 补充输入

行动一经领取，原输入冻结。失败后重新排队不再重新开放补充，以免新输入和旧工具步骤混用。
尚未领取的行动仍可补充，且同一事务验证领取状态。

未发送补充保留在页面内、按账号／战役／行动隔离；切换标签或战役可恢复，不写localStorage。
刷新页面／关闭应用仍会清除未保存草稿。若原行动已冻结，文字不会被清空，
可明确点击“转为新行动草稿”，核对后再提交；转换本身不发送行动。

## 记忆建议分页

房主接口 `GET /memory-suggestions?paged=1&status=pending` 返回：

```json
{"items":[],"total_pending":0,"has_more":false,"next_before":0,"status":"pending"}
```

每页20条，下一页携带 `before=next_before`。状态可为pending/accepted/rejected/all。
待确认数量是整个战役总数，不是本页条数。页面提供待确认、已采用、已忽略和全部记录筛选，
旧的待审核项不会被最新100条已处理记录挤出。
为兼容旧客户端，不带paged仍返回数组（最多100条），但优先返回待确认项。

Go覆盖四人9工具步骤的内置恢复、资源只扣一次、续租绝对上限、主持／版本边界、
领取后补充冻结、45条待处理建议跨页且不被已处理记录遮蔽。
`test:reliability`另验证外部Bot的进程间检查点恢复、草稿往返与冻结转换、分页界面。
均为隔离服务／无头验收，不代表付费模型账户和所有长时网络场景均已测试。
