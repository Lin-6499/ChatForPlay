# 地产大亨首版设计稿

状态：已按本设计完成首轮本地实现；使用与接口见 [ESTATE.md](ESTATE.md)。尚未发布部署，数值仍需试玩调优。2026-11-26。
用户已确认：主要电脑端。沿用 LinChat 外观系统、黑白 LC 标识及娱乐入口。
界面模式：Operate；核心任务是看清局势并完成当前回合。

## 1. 首版目标与边界

- 2–4名真人，原创24格棋盘，固定12轮；目标单局20–30分钟，需实测，非时长保证。
- 形成准备、开局、买地、升级、收租、偿债、结算的完整闭环。
- 同房聊天与对局同时可见，断线后恢复，离线玩家按公开规则自动操作。
- 首版包含抵押、赎回、拆建、固定事件；玩家交易、拍卖、观战入口、AI玩家、角色技能留待后续。
- 首版使用规则化播报即可玩完整局，不依赖模型调用。AI解说作为后续增强。
- 游戏货币仅限本局，无充值、提现或账号间转账。

## 2. 入口与准备房

娱乐首页增加“剧情战役”“地产大亨”两种类型；保留已有战役的深链接和继续入口。
地产房间与一个游戏群绑定，复用成员身份、邀请及聊天；独立游戏状态，不复用剧情主持租约。

创建表单：房间名（1–40字）、人数上限（2/3/4，默认4）。
地图“环城商业街”、12轮与超时规则固定展示，不允许房主临场修改。
加入后选择1–4号圆形棋子，内部标出编号，使用独立蓝／橙／紫／绿实色辅助区分，编号唯一；支持键盘选择。
至少2人且全员准备后房主可开始。服务器随机一次生成顺序并记录，整局不变。
开局后不能补位；退出界面只视为离线，不删除参赛者。
准备房房主离开时移交最早加入者；开始后规则自动运行，不依赖房主在线。

## 4. 回合状态与倒计时

```text
lobby → management → roll → resolve
                              ├→ purchase_decision → end_turn
                              ├→ market_decision → end_turn
                              ├→ debt → end_turn
                              └→ end_turn
end_turn → 下位玩家的management / finished
```

- 管理与等待掷骰共用45秒：可升级、拆建、抵押、赎回，点击“掷骰”即关闭管理阶段。
- 超时自动掷2d6；双骰相同不额外行动。服务端决定点数、路径、落点，不等待动画回执。
- 无主地产显示“购买 · 金额”“放弃”；20秒超时放弃，不触发拍卖。
- 市集选择20秒，超时离开；现金不足不能购买，不能为自愿购买进入债务。
- 自己地产、休息、缴税、收租、固定事件均自动结算，不额外要求点击结束回合。
- 普通结算完成后可保留最多2秒展示节拍，由服务端设定下回合开始时间，不依赖任何玩家客户端。
- 每位未破产玩家获得一次回合机会计一轮；检查导致跳过也算机会；第12轮完整结束后结算。
- 中途破产跳过其后续座位；只剩一位未破产玩家立即结束。实现应防御全员破产并明确记录无胜者。

### 检查规则

被送到检查中心时结束当前回合，不领起点奖励；普通骰子落在12不触发检查。
下一回合在45秒内选择“支付100，立即正常行动”或“停业一回合”。
不足100只能停业；超时默认停业。停业结束自动解除，下次回合正常行动。
选择停业时不能进行资产管理；一次检查最多损失一个回合。

## 5. 债务、清算与终局

强制支出不足时进入60秒债务处理，现金保持非负；记录待付金额和单一债权人，不先减成负数。
期间仅能拆建和抵押，不能买地、升级、赠送资产或发起其他行动。

- 每拆一级退还该级建设费50%，不能拆到低于1级。
- 只有1级普通地产及枢纽能抵押，所得为地价50%；赎回为抵押本金110%，向上取整。
- 现金够付时立即一次性扣款并向债权人入账，退出债务阶段。
- 超时按固定顺序：先拆级数最高建筑（平局按格号），再抵押地价最低地产（平局按格号），到够付即停止。
- 全部可清算资产仍不足时破产：剩余现金付给债权人，余债注销，所有地产回银行、等级重置、抵押清除；免租券作废。
- 上述回收规则对银行和玩家债权人一致；不会把整组土地直接送给债权人形成连锁优势。
- 破产玩家保留聊天与本局查看权限，失去游戏操作权限。

终局按净资产降序排名：

`现金 + 未抵押土地原价 + 各已建等级的拆建返还额 + Σ(已抵押土地原价−赎回价)`

抵押剩余价值按0下限计算；终局不允许留有未处理债务。免租券不计价值。
同净资产比较现金，再比较未抵押地产数量；仍相同则并列。破产玩家列于存活玩家之后，按存活回合数排序。
结算页列出资产分项、总收租、最大单次付款、破产顺序和可回看的事件列表。
“再来一局”创建全新准备局，玩家重新准备，不覆盖旧记录。

## 7. 桌面交互与布局

继承现有主题派生变量、系统字体、控件和焦点样式；产权组用A/B/C/D＋色条，玩家用姓名＋形状＋颜色。
设计基准1440×900，关键验收包含1280×720与用户常见的820×738小窗口。

```text
┌ 娱乐 / 地产大亨   环城商业街    第4/12轮   连接状态 ┐
├─────────┬────────────────────────┬──────────────┤
│ 玩家顺序 │                        │ 当前操作      │
│ 姓名现金 │      7×7外圈棋盘        │ 待你掷骰 32s  │
│ 地产数量 │                        │ [掷骰]       │
│ 当前标记 │      中央：骰子结果     ├──────────────┤
│         │      /选中地产详情      │ 聊天 | 对局记录│
│ 我的资产 │                        │              │
│ [管理]  │                        │ 输入框        │
└─────────┴────────────────────────┴──────────────┘
```

- 宽窗口：左侧约184px，右侧约300px，中间棋盘自适应；棋盘始终为正方形。
- 960–1199px：玩家列表变为顶部紧凑横排，保留棋盘与右栏。
- 低于960px或高度不足：棋盘占主要区域，聊天抽屉，操作固定在棋盘下方；不把7格强行压成不可读文本。
- 手机兼容：格子显示编号、组别、主人形状；点选后显示完整名称和价格。另提供线性“地图列表”访问全部格子。
- 棋盘上格子可聚焦，方向键导航、Enter查看；文字不随棋盘边旋转。
- 当前操作固定在右上，与浏览资产分开。查看别人的地产不能盖住自己的购买决定。
- 中央地产详情显示价格、租金、主人、等级、抵押状态；有权限时才显示可执行管理动作。
- 聊天和记录独立滚动；阅读历史时新消息不拉回底部，提供未读提示；保留现有位置记忆约定。
- 买地无需二次弹窗：按钮直接写“购买 · 300”，旁边显示“余额1250 → 950”。
- 非本人回合显示“等待小满掷骰”，不放一个无法解释的灰色掷骰按钮。
- 债务面板显示“待支付270 / 现金120 / 还差150”，每个资产标出可回收金额和失去的租金。
- 倒计时旁始终说明到期动作，如“20秒后自动放弃”；不只显示数字。

### 反馈与异常

- 请求中禁用重复操作；网络不确定时查询同一操作结果，不新建请求编号再次购买。
- 版本冲突刷新快照，提示“局面已更新，请重新确认”；保留尚未发送的聊天草稿。
- 离线横幅说明“重连中，回合计时仍在继续”；禁止客户端本地推算扣款。
- 断线重连直接恢复权威位置、现金、阶段与截止时间，不补播整段棋子行走。
- 掷骰动画约0.8秒，移动总时长不超过1.2秒；减少动态效果时立即显示落点及路径文字。
- 视觉与键盘操作均不依赖动画结束事件；重要结算用简短可访问播报，逐秒倒计时不连续朗读。
- 全员离线仍按超时规则推进至终局，初版不另设暂停／投票状态。

## 8. 工程接入草案

复用现有账号、群成员校验、聊天、WebSocket、主题及骰子视觉；独立实现地图、回合及现金账本。
建议模块：`EstateLobby.vue`、`EstateGame.vue`、`EstateBoard.vue`、`EstateActions.vue`、`estate-types.ts`及Go棋盘规则服务。
数据至少包含：room、match、player、property、deck、event、operation；规则版本`estate-v1`绑定每局。

每次操作在一个事务中：校验成员/操作者/阶段/版本 → 校验余额 → 应用效果 → 写事件 → 版本+1。
请求携带`client_id`和版本；超时事件也有唯一键，进程重启扫描未完成期限，不能重复代掷或扣租。
事件带连续序号；WebSocket仅作变更通知，快照与日志支持重连补齐。
客户端可见快照不含随机源、牌堆顺序、其他账号秘密。

接口建议：
- `POST /api/v1/estate/rooms`，创建准备房；
- `POST /api/v1/estate/rooms/{id}/join|ready|start`，准备操作；
- `GET /api/v1/estate/matches/{id}`，公开成员快照；
- `POST /api/v1/estate/matches/{id}/actions`，判别联合动作roll/buy/decline/upgrade/sell/mortgage/redeem/check_release/check_wait/market_buy/market_leave；
- `GET /api/v1/estate/matches/{id}/events?after_seq=...`，事件增量。

动作只接受所需参数，例如buy不接受客户端传入的价格、租金或现金结果。
骰子结果、卡牌与钱款均在服务端生成；普通聊天绝不解析成购地指令。

## 9. 开发拆分与验收

1. 规则内核：地图/牌表、回合状态机、债务与净资产；用固定骰子和牌序覆盖关键路径。
2. 多人服务：准备、认证、快照、幂等、事件、超时恢复；验证两端竞争及中途重启。
3. 桌面界面：棋盘、当前操作、资产、聊天、结算；补齐小窗口和键盘操作。
4. 隔离试玩：2/3/4人完整12轮，采集时长、地产购入率、升级次数、破产率与先手胜率。

必须通过：
- 重发同一掷骰/购买请求仅执行一次；他人、越阶段、过期版本操作被拒绝。
- 买地、收租、抵押、赎回、拆建和终局金额与规则表一致。
- 免租券、检查、起点奖励、移动卡与最后一轮不产生重复结算或额外回合。
- 自动清算和人工清算同一规则，60秒到期与人工付款并发不会双扣。
- 四人刷新/重连后资产一致；服务重启能继续倒计时并完成对局。
- 1440×900、1280×720、820×738与390×844下当前动作可达，无页面横向溢出。
- 使用隔离数据与无头浏览器，不操作正式账号或打开可见应用窗口。

数值为第一轮试玩基线，尚未做平衡验证。主要观察风险：短局内建设回本偏慢、先手多买地、事件现金注入过高。
优先调租金、起点收入和升级费；若完整局时长超目标，再调整操作期限，不能直接声称12轮等于20分钟。
