# 文字跑团优化推进

用户确认按三项顺序推进；不引入地图／棋盘。

1. **剧情进度与记忆整理**（已验收，云端及GitHub1.2.11已交付）
   - 本幕章节与关联资料的一次选择。
   - 任务／线索的独立进度，保留有效／归档含义。
   - 回合完成时提交待确认的记忆建议，只有房主采用并保存后才成为事实。
   - 使用已保存摘要、正式叙述与公开任务整理可追溯的前情回顾。
2. **玩家行动与主持节奏**（已验收并随1.2.12发布、部署云端）
   - 当前行动者、排队者、等待原因。
   - 逐人／全员收集节奏，未领取行动补充及快捷回复状态。
   - 失败原因与恢复操作。
3. **主持接入自检**（已验收并随1.2.12发布、部署云端）
   - 版本／协议／能力发现接口、外部主持启动检查。
   - 统一接入说明与最近活动诊断。

约束：隐藏／无头、隔离数据测试；公开与秘密权限不放宽；不覆盖主分支并行更新。
第一项与后续项分别验证、记录交付状态，不将未完成项描述为已上线。

## 下一阶段实现边界

- “全员收集”不能伪装成“只是延后逐个处理”：需要明确收集成员，保持每条行动的actor与event_id；
  联合回合如需多个检定，应让租约校验认可同一批次的各个行动，不能把玩家行动归给机器人。
- 收集期间不得让内置worker或外部claim提前处理。离队、超时、未提交成员需显示原因，
  房主可明确结束收集；不能自动替玩家选择或提交行动。
- 未领取补充采取追加有审计记录的补充，不悄悄改写已保存聊天。
- 与正在运行/已掷骰回合的兼容、重试去重、上下文不夹带后续批次行动均需测试。
- 第三阶段能力接口应只返回能力及诊断，不返回token/lease/API key/秘密正文。
